## MARVEL-581 The Hood (`hood`, mc24)

Inventory: 74 joined numbered faces, 74 upstream rows. The ledger covers `24001`–`24011` Hood scenario, nine modular sets—Beasty Boys, Brothers Grimm, Crossfire's Crew, Mister Hyde, Ransacked Armory, Sinister Syndicate, State of Emergency, Streets of Mayhem and Wrecking Crew—and seven Standard II plus four Expert II faces. `pack:mc24:modular-sets` names the nine; `pack:mc24:alternative-sets` permits Standard II to replace Standard and Expert II to replace Expert in otherwise eligible scenarios. These are reusable sets, not merely Hood extras. The scenario has normal I/II and expert II/III stages, with main schemes `24004a/b`, `24005a/b`, `24006a/b`.

`24004a` requires choosing **seven** modular sets, putting them aside, then choosing one of those at random to shuffle into the encounter deck. `24002`/`24003` and scheme transitions inject another random set. This needs a seeded, ordered set pool that survives save/replay; do not shuffle an already active set again. `24001`–`24003` Foul Play discards one or two encounter cards and deals qualifying non-Hood cards facedown; stage III deals **each** qualifying card, while stage II deals only the first. `24005b` adds two threat per player who received no card. Test an all-Hood discard, mixed discard and encounter-deck exhaustion; compare same-seed set selection after restart. `ruling:5eda4eb920cf9af6` clarifies a late-injected set's Setup/Permanent cards remain set aside until that set enters, then process their setup conditions. `pack:mc24:important-keywords` defines Steady, Villainous, Hinder, Incite, Permanent and Setup. Card catalog keyword recognition (`CardCatalogJson`, `StateFieldCatalog`) is only a data primitive; prove two stun/confuse statuses, boost assignment to a Villainous minion and correct discard/boost timing in engine tests before treating them as supported. `ruling:5268a59b0aac2c20` makes `24033` Self-Experimentation a useful mutant: a 15-damage attack against a 7-HP Brute can remove 15 threat rather than cap at remaining HP. Other distinctive sets include Brothers Grimm's attachment search, Crossfire's ally attacks, Mister Hyde's identity transformation, State of Emergency repeating each in-play side scheme's When Revealed, and Wrecking Crew's minions, which are not the separately admitted Wrecking Crew scenario.

First nonpublic engine/content slice: add seven-set seeded setup and one Hood/Foul Play path through engine setup → stage transition → save/restart, with a no-eligible-card negative case. Then implement set injection and nine complete modular rows before public admission; prove Standard II/Expert II substitutions against a Core scenario with their true quantities. UI needs an explicit selected/remaining modular-pool view and source-labeled facedown card results. Authority question: the local insert records broad substitution but does not enumerate every original physical card back/divider; verify original PDF/component list before claiming a reconciled physical manifest.

`FormDataTests` is only structural evidence that `26002a/b` print Mass Form; check `Forms.Of`, `Characteristics`, `CardEntry` and attack/defense admission for live behavior. ## MARVEL-586 Ironheart (`ironheart`, mc29)

Inventory: 43 joined/upstream faces, six faces `29001a/b`–`29003a/b` on **three physical identities**, signature `29004`–`29013`, `29028` obligation, `29029`–`29032` Lucia von Bardas nemesis, and `29033`–`29039` later/basic cards including Zzzax modular. Pre-divider Leadership starter is a **candidate**. `pack:mc29:hero-pack` OCR is doubled/interleaved, but its progression clause clearly requires one HP dial and transfer of attached elements/statuses/tokens across versions; inspect original PDF before encoding edge wording. `ruling:063411d2bc4993bb` mirrors this rule.

`29001b` begins the game and sets the other identity versions aside. Version 1's `29001a` spends six progress, readies and swaps to Version 2. Version 2's `29002a` additionally gains Tough on swap to Version 3. Every version shares one HP dial; damage and all attached elements persist; defeating any version eliminates the player. A version swap is not a hero/alter-ego flip and must preserve round limits, attachments, owner and source IDs while updating printed stats/hand size/traits. Child Prodigy's payment alternatives differ by version. `ruling:45d4c6a8aa3ea5f2` distinguishes Limit from Max for the per-round ability on a **new** identity instance; read the complete answer and align the RR's current limit semantics before deciding whether a version swap grants another use in the same round. `29005/06` grant two progress only on last threat/enemy defeat; `29007` chooses X **different** effects according to current version; Version 3 `29003a` spends progress for repeatable damage. `29008` permits encounter-deck top inspection until round end, requiring visibility scoping and no RNG/query mutation. `29028` on zero progress deals an encounter card and shuffles the obligation into that deck. Zzzax tests must count printed energy on controlled cards; Haywire changes printed resources in hand while attached, so the exact distinction needs a ruling-backed check before implementation.

First nonpublic engine/content slice: Version 1 setup → six progress → swap to Version 2 with damage/status/attachment intact → save/restart → next decision; negative control at five progress, a defeated identity, and repeated same-round limit. Then Version 3, multi-choice `29007`, top-deck visibility, obligation and both nemesis/modular sets. The client needs a clear current-version marker, progress/cost and next-version consequences; use a native journey. If progression requires a materially new UI affordance, prepare captured behavior and a focused Plane review item, while authority and engine tests remain agent-owned.
