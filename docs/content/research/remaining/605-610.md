**Rules and proof.** `48006` Bamf! attaches to an enemy (one per enemy), then is discarded when that enemy attacks to declare Nightcrawler the defender **without exhausting**. `ruling:031ecd262c8e15ea`/`ruling:2cd5a415f9f43451` explicitly permit this while he is already exhausted. `ruling:66ab8d7d3bfa3e05` resolves an early Bamf! declaration against Melter's later defend-with-ally requirement. The attachment's host, attacker, defending player and hero must remain separate identities in multiplayer; `48011` Tally Ho! returns the just-discarded copy and damages that attacker, while `48007` hits all enemies currently bearing Bamf!. `48001a` pays one resource to recover Bamf! from discard once **per phase**, whereas `48001b` searches the deck once **per round**. `48004` counts as two restricted cards and `48005` changes restricted capacity. The product insert `pack:mc48:nightcrawler-protection` confirms the defend/return/replay sequence, but it is explanatory, not a starter list.

First bounded engine slice: attach Bamf! to an enemy engaged with another player, start its attack, declare an exhausted Nightcrawler as defender, use Tally Ho!, then save/restart with the copy in hand and correct defender/damage history. Test a different attacker, duplicate Bamf! on one enemy, missing discard target, insufficient resource, each limit resetting at the proper boundary, and `48027` Azazel/independent Crazy Gang before whole-pack admission. View/Decisions must name who attacks whom and whose Bamf! will be discarded before commitment. A concrete native approval item is needed only if this working cross-player defender substitution creates a materially new interaction.
