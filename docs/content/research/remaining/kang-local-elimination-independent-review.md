Reviewed revision: `d557ecc10649d93c57ca0ba77cf3932a3ef685da`; base `c91cd4f26ecb0e317a9dba51703da4b6e76b6e85`. Verdict: **request changes** for this bounded nonpublic capability. This is not a Kang pack readiness assessment.

1. `KangElimination.Preflight` identifies a suspended departure only when the eliminated player's area still has a local 3B. After Kang II is defeated, that group's 3B has been removed and `Begin` removes the departure from `Pending`. Eliminating its player while the join prompt is suspended therefore returns normally and changes the group rather than raising before elimination mutation. `EliminatingDepartingPlayerDuringSuspendedJoinRejectsBeforeMutation` reproduces the missing preflight. This synthetic direct-call probe establishes the advertised elimination boundary, not that a normal player can act while a join prompt is pending. Damage placement itself precedes defeat/elimination, so no whole-damage rollback is inferred.
2. `KangPhaseTransitions.PlayerDeparted` replaces the captured group with all current members. An uncontrolled prior membership change is thereby accepted when a genuine player elimination follows. `EliminationMustNotRebaseUnrelatedChangesToCapturedGroup` joins a third player after capture, eliminates the captured player, and demonstrates that the phase boundary no longer rejects the stale capture. Only the actual eliminated member may be removed from an otherwise unchanged capture; the earlier stale-group guard alone does not cover this composition.
