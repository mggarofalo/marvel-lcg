## Repair

`EnclosingAbilityContinuations.For` reads only the current decision's ancestor
execution frames and rejects a stale frame. Cards finds the parent with the
captured physical Invocation, incarnation, owner and paid Special cost. The
checked parent ability supplies its action name and successful exact-return
instruction; accepted typed costs supply exhaustion. The existing typed Special
instructions supply independent discard and public-top refresh. A synthetic
Special without discard receives no discard promise.

Cards adds this explanation to existing `Prompt.Description`, retaining the
current recipient/replacement explanation. View, Decisions and Godot already
carry that field. Protocol 42 is unchanged; no new wire field, renderer rule,
card-text parsing, dataset change, or public content admission is involved.

The screen says which action is continuing, which costs are already paid, what
was exhausted, what happens to this Invocation after its choices, and that
closing the choice does not refund costs. Hidden future titles/order are never
looked up for this explanation. An unauthorized seat receives no private prompt.
