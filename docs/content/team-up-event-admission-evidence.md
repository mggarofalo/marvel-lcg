Candidate based on `c43057003d1e85be4d176e37ddefb25a3f9e9193`. This is an engine prerequisite, not admission of Ant-Man content.

Rules Reference 1.8 `rr:team-up` and `.1` require both named friendly identities or allies in play before playing the card; `.2` includes an ally's subtitle. `rr:identity.4` makes only the faceup identity side in play. `rr:loses` makes a lost keyword nonfunctional. The vendored rulings confirm friendly characters, ally subtitles and following the event's other form restrictions; the current reference governs. No Team-Up or Swarm Tactics hit was found in the vendored MarvelCDB FAQ index.

Existing ordinary card play calls `CardPlayLegality.TeamedUp`, including its characteristic-loss and friendly-character matching. Event action discovery previously checked only playable origin; event window discovery had the same omission. This candidate exposes that rule-owned predicate to the ability engine and uses it for action and out-of-play window event admission. It checks a captured card-play offer again at `Game.Resolve` before information clearing or commitment, while leaving in-play event triggers outside this play restriction.

Synthetic in-play event triggers exercise discovery and public resolution without applying a new play restriction. These synthetic cases are boundary probes, not a claim that such an event is admitted in a product. Existing ordinary-play Team-Up tests remain intact.
